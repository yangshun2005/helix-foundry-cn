# 实现与验证

这是一个可执行的单服务器 MVP。以下验证结果来自本地开发机器，并非生产环境 SLA。大部分结果记录于 2026 年 9 月 23 日至 24 日。发布读取基准测试（见[基准测试](#基准测试)）以及重写后的备份、恢复和升级脚本的测试来自 2026 年 10 月 10 日，两者均标注该日期。

重写后的 `scripts/backup.sh`、`restore.sh` 和 `upgrade.sh` 目前仅在测试中针对桩 `docker` 运行过。在它们针对真实的 Compose 安装运行之前，这就是它们唯一的覆盖范围；参见[备份、恢复和升级脚本](#备份恢复和升级脚本2026-年-10-月-10-日)。

## 已验证路径

- 原生 HelixDB v0.0.6 持久化、带索引的工作区身份、条件原子元数据写入、过期写入拒绝、原生对象关系以及关系删除。
- 真实的 DuckDB Parquet 摄取、性能分析、聚合、输入过滤、可视化 DAG 编译、与文件/网络/未声明输入的隔离，以及被拒绝的多语句 SQL。
- 所有者引导、本地会话、一次性邀请、角色检查、范围限定的只读令牌、跨工作区 API 拒绝以及跨源变更拒绝。
- 黄金客户/订单：精确指标和关键检查、引用覆盖、源新鲜度守卫、保留的手动描述、Schema 漂移暂存、可恢复的 AI 检查点、手动对象，以及重新物化后仍然保留的关系编辑。
- MySQL 8.4：information_schema 发现、键/列、有界流式传输、大无符号整数、DECIMAL(30,8)、时间字符串、Unicode、空值、通过 Parquet 的保留、Schema 变更、认证/TLS 错误，以及故意中断的连接。调度和重复作业合并使用受控连接器单独测试。
- REST 偏移分页和跨源凭据保护；使用本地协议夹具的 S3 兼容列表和流式传输。
- 原生 Ollama、Claude Messages 工具输出和 OpenAI Responses JSON-schema 适配器具有协议测试。提供程序错误不会触发回退。
- Chromium：登录、空状态和已连接状态、全部六个添加数据选项（包括 MySQL/TLS）、经过测试的业务模型审查、发布、已保存仪表板选择和深层链接、相关记录导航、预览编辑和历史记录、未更改的快照结果，以及查看器控件。桌面和 390px 移动布局已进行视觉检查；模态框 Escape/焦点恢复和移动导航已覆盖。
- Docker 镜像构建和四个数据平台服务启动。一次 Compose 安装摄取并查询了示例数据。其 Helix 和 Parquet 卷的备份/恢复保留了一个工作区、三个数据集和 340 行。该次运行在 2026 年 9 月，使用的是较早的 `backup.sh` 和 `restore.sh`，它们将 `.env` 复制到备份中。重写后的脚本尚未针对真实安装运行；它们的桩测试描述见[下文](#备份恢复和升级脚本2026-年-10-月-10-日)。

## 连接、理解和行动重新设计

该重新设计通过了 35 个默认单元/API/工作流测试和两个浏览器验收测试，以及 TypeScript 检查和生产构建。默认运行跳过三个可选的 Helix/MySQL 集成测试；连接器实现未因重新设计而更改。浏览器测试使用隔离的工作区，并在之后删除其数据。

新覆盖范围验证了答案/构建自动路由、计入的模型使用量、恢复时保存的路由决策、格式错误的输出、调用限制、取消、生成前的查看器拒绝、授权的资源上下文和后续操作、托管掩码、稳定的逻辑记录路由、有效值过滤器以及跨工作区记录拒绝。现有测试继续覆盖过期审批和编辑、定义回滚、刷新保留的覆盖层以及发布验证。来自订单记录的实时本地 Qwen 请求自动选择了答案、执行了 SQL，并返回了 35 个延迟订单及来源引用。已发布视图、记录操作、数据检查和浏览器参考工作流不需要推理。

## 本地 AI 工作流

一个干净的参考工作区使用摘要固定的本地 `qwen3:4b` 完成了从目标到审查的工作流。给定示例数据集和关于客户收入及延迟订单的目标，它生成了三个目录条目、一个 SQL 流水线、Customer 和 Order 本体类型、一个关系以及一个双组件仪表板。自动验证修复了本体和仪表板草稿；所有十项最终检查均通过，无需手动编辑组件。随后通过 API 发布了审查后的包：

- 32 个客户对象和 240 个订单对象。
- 240 个客户/订单关系，覆盖全部 32 个客户。
- 按区域分组的收入以及恰好 35 个延迟订单。
- 每个已发布查询均针对声明的快照版本执行。
- 六次本地模型调用、14,516 个报告的 token，从第一阶段到就绪提案约 153 秒。发布时间单独计算。

数据集名称引用仅在唯一标识授权目录条目时才会解析。当生成的指标具有多行时，图表呈现方式根据执行结果形状推断。这些是技术性修正，不是虚构数据或伪装成模型输出的模板。业务假设仍然可见以供人工审查。此工作流未使用托管模型调用。

## 基准测试

在配备 16 GB RAM 的 Apple Silicon M1 Pro 开发机器上：

| 工作负载                              | 测量值 |
| ------------------------------------- | ----------: |
| NDJSON 转 Parquet，1,000,000 行       |      472 ms |
| 并发分析 HTTP 客户端                  |          25 |
| 执行器槽位                            |           2 |
| 包含排队时间的中位响应时间            |    1,690 ms |
| 包含排队时间的最慢响应时间            |    3,139 ms |

此基准测试不包括推理，测量的是执行器工作负载，而非 25 个浏览器会话。记录的 149 MB RSS 仅为基准测试客户端，不得表示为组合平台内存。在执行器可用的情况下运行 `BENCH_HTTP=1 pnpm benchmark` 以复现。硬件、热缓存、存储和查询形状会改变结果。

该基准测试还计时了发布如何读取具有一百万条记录的类型。在同一台机器上，进程内（2026 年 10 月 10 日），一次物化查询以 JSON lines 形式读回耗时 2.1 秒。它所替代的路径运行了 2,000 次查询，每次加载并分析整个表，每次 196 ms，在 HTTP 和子进程启动之前约 6.5 分钟。两个数字都不包括将记录写入 HelixDB。

## 引导式入门验证（2026 年 9 月 24 日）

可恢复的设置增加了持久的提供程序准备和上传/导入进度、明确的源选择、有依据的结果推荐、内联修订和经过测试的预览，以及绑定发布的完成。该套件通过了 46 个默认测试、三个隔离的浏览器测试、四个 MySQL/PostgreSQL 集成检查，以及一次真实的固定 Qwen 入门评估。TypeScript 和生产构建通过。

本地评估在 117 秒内完成，包含一次推荐调用、五次构建/修复调用、7,631 个报告的模型 token、十项通过的验证检查和一个已发布仪表板。它未使用托管提供程序。浏览器测试使用确定性提供程序夹具加上真实 DuckDB；这些是与真实模型运行分开的证据。桌面和 390px 设置/审查布局均已检查。现有发布、相关记录编辑、已保存视图选择和查看器屏幕仍然通过。

浏览器验收现在在端口 3101/3102/5174 上启动单独的安装，具有自己的元数据存储和数据目录。它无法引导或播种实时安装。在此更改期间未创建演示账户或实时示例数据。有关路由、幂等性、恢复和夹具命令，请参见[入门](onboarding.md)。

## 备份、恢复和升级脚本（2026 年 10 月 10 日）

重写后的 `scripts/backup.sh`、`restore.sh` 和 `upgrade.sh` 将密钥排除在备份之外，并且 `upgrade.sh` 在每次升级前进行备份。它们尚未针对真实的 Docker 或 Compose 安装运行：在运行之前，下面的桩测试是它们唯一的覆盖范围。

已验证的内容：`tests/scripts.test.ts` 在带有裸上游的一次性 git 检出中针对桩 `docker`（`tests/fixtures/fake-docker.sh`）运行脚本。它检查每个脚本进行的 Docker 调用及其顺序、没有密钥、客户端机密或密码短语到达备份、输出或另一个命令（也在 `bash -x` 下）、文件模式、必须不改变任何内容的失败路径、必须重新启动服务或必须删除失败备份所写内容的失败路径、未设置的 `HOME`、完成未完成的升级、HelixDB 镜像检查、`foundry-data` 归档排除执行器的 `scratch` 和 `results`（使用本机的 `tar` 代替镜像的 BusyBox `tar` 归档本地文件夹），以及使用 `upgrade.sh` 打印的命令回退，也可回退到 `upgrade.sh` 之前的发布版本（该发布的脚本位于 `tests/fixtures/release-before-upgrade`）。这些测试在 macOS 上使用 bash 3.2 和 BSD 工具、在 OpenSSL 3 和 LibreSSL 3.3 下运行。CI 在 `ubuntu-latest` 上运行它们。脚本编码的 HelixDB 存储事实来自 HelixDB 发布说明。

尚未验证：

- Docker 在 Compose v2 下记录为 HelixDB 容器镜像的内容（`docker inspect --format '{{.Config.Image}}'`）。脚本先按摘要、再按版本将其与 `compose.yaml` 中的固定值进行比较。如果 Docker 仅记录了镜像 ID，`restore.sh` 将拒绝新备份并显示"无法判断哪个 HelixDB 版本更新"，而 `upgrade.sh` 将永远不会报告"已是最新"。
- 使用 `alpine:3.22` 归档和恢复真实卷，包括 BusyBox `tar` 对 `scratch` 和 `results` 排除项的处理、停止和重新启动真实服务，以及 `upgrade.sh` 和 `restore.sh` 中的重建和重启。
- 跨 HelixDB 固定值变更的真实升级，以及从中回退。
- 使用真实密码管理器的 `--env-file <(COMMAND)`，以及 CI 之外 Linux 上的脚本。

在依赖它们之前，请针对真实的 Compose v2 安装运行一次 `backup.sh`、`restore.sh` 和一个发现安装已是最新的 `upgrade.sh`，并检查 `docker inspect --format '{{.Config.Image}}' $(docker compose ps -q helix)` 打印的内容。

## 剩余验证和 MVP 限制

- Claude/OpenAI 实时检查需要提供的凭据。没有可用的托管凭据，因此仅运行了协议夹具。
- 组合的 16 GB 本地推理目标和限制为 8 GB 的安装仍需要专门的峰值内存/负载认证。百万行基准测试并不认证百万对象本体发布。
- PostgreSQL 16 多表导入、认证/TLS 失败和 Schema 漂移已在隔离容器中验证。部署特定的证书链和真实 S3 服务仍需要环境集成测试。
- 入门支持多表和多文件选择，每个表/文件保留一条源记录。用户明确选择选择项；相关表根据发现的外键建议。
- 高级本体图显示前 100 个对象。记录使用 50 行分页，支持搜索和精确过滤器；关系选择在工作区中搜索，每次 50 个结果。元数据列表当前在切片前读取范围限定的集合，因此非常大的本体部署需要存储级分页。
- 可视化 DAG 覆盖常见的关系转换；专用 SQL 仍可编辑。被拒绝行的证据可用于保留候选键的单输入流水线。有歧义的连接仍需要业务审查。
- 后台协助在更改后准备修复草稿。修复是有界的，可能仍需要更大的模型或开发人员编辑。它从不自动发布。
- 操作历史和导入值是分开的。回滚会根据当前快照重新验证先前的定义并重新物化它们，保留手动覆盖层；它不会撤销业务操作。
- 查询执行是隔离且有上限的；此版本不提供与外部源的分布式事务、CDC、SSO、计费或按记录的 LLM 增强。
